# Запуск Adjust через Remote Config

SDK использует встроенный строковый A/B-параметр `adjust_enable`. В новых установках
Remote Config включён по умолчанию; добавлять A/B-тест или обработчики вручную не требуется.

| Значение | Поведение после полного перезапуска приложения |
| --- | --- |
| `"true"` | Запустить Adjust, если модуль включён в SDK Settings и задан токен. |
| `"false"` | Не вызывать `Adjust.InitSdk`, не отправлять события и ad revenue через Adjust SDK. |

## Настройка

1. В **SDK Settings → Adjust** включите модуль и задайте app token.
2. Установите и настройте Firebase для приложения, включите модуль **Firebase** в SDK Settings.
   **Enable Remote Config** уже включён в новых настройках. Если в существующем проекте он был
   явно выключен, включите его и сохраните настройки: сохранённое `false` автоматически не меняется.
3. В Firebase Console создайте параметр **adjust_enable**, тип **String**, значение **true**.
4. Чтобы отключить Adjust, опубликуйте значение **false** и полностью перезапустите приложение.
   Перезагрузка игровой сцены не перезапускает SDK, который живёт между сценами.

Для всех пользователей задайте обычное значение без условий/эксперимента, переопределяющих этот ключ.
Для A/B-теста задайте строковые варианты `true` / `false`, аудиторию и доли в Firebase Console.
Для эксперимента Firebase A/B Testing также нужен включённый Firebase Analytics.

Регистрация теста и двух обработчиков выполняется автоматически при запуске SDK, в том числе
с пустым списком **A/B Tests**. Отдельная кнопка или игровой код для этого не нужны.
Для обращения из кода доступны константы `AMZNGoDSDK.Runtime.FirebaseSettingData`:
`AdjustEnableTestId`, `AdjustEnabledGroup`, `AdjustDisabledGroup`.
Существующие записи в A/B Tests и сгенерированные для них константы продолжают поддерживаться;
удалять их при обновлении не требуется.

## Порядок запуска и кэш

- Ядро откладывает Adjust, запускает Firebase и ставит `Run("adjust_enable")` в очередь обычного A/B-реестра.
  Обработчик выбранной группы разрешает или запрещает инициализацию. Затем стартуют остальные модули SDK.
- При включённых Adjust и Remote Config выполняется `FetchAsync(TimeSpan.Zero)` и активация:
  обычный интервал A/B-конфига в 12 часов не мешает проверке на следующем запуске.
  Это общий запрос Remote Config, поэтому он также обновляет остальные A/B-параметры.
  Firebase может отказать в запросе, в том числе из-за ограничения частоты.
- Ожидание ограничено таймаутом fetch из SDK Settings плюс 5 секунд на подготовку и активацию
  (по умолчанию максимум 15 секунд). Это ожидание использует реальное время и не зависит от `timeScale`.
- При сетевой ошибке или таймауте используется активированное значение из кэша Firebase.
  Если оно недоступно, используется последнее применённое решение, сохранённое в PlayerPrefs.
  На первой установке без доступного значения — `true`.
- При успешной загрузке отсутствие ключа, пустое значение или неизвестная строковая группа возвращает контрольную `true`.
  Значения чувствительны к регистру: `False` не является группой `false`.
- Решение фиксируется на текущий запуск. Поздний ответ после таймаута не запускает Adjust и
  не меняет A/B-группы посреди сессии. Следующая проверка — после полного перезапуска.
- Если Firebase или Remote Config выключены, Adjust стартует по локальным настройкам без ожидания.
  Удалённое `true` не включает локально выключенный модуль.
- Общий модуль Internet Connection, если включён, по-прежнему может ждать сеть перед запуском всего SDK.

Выбранную группу можно прочитать через `TryGetABTestGroup("adjust_enable", out var group)`.
Ключ и обработчики зарезервированы для SDK: не удаляйте и не переопределяйте их игровым кодом.
`ab_test_exposure` обозначает применение решения о запуске, а не подтверждение native-инициализации.
AppMetrica на этом раннем этапе может быть ещё не запущена; событие получает доступная аналитика.

## Границы флага

Флаг управляет инициализацией встроенного Adjust SDK. Атрибуция из него и отправка ad revenue также
проверяют готовность модуля. Чтение Amazon Fire advertising ID для собственной аналитики остаётся:
утилита `GetAmazonAdId` в Android SDK 5.4.5 читает ID устройства без инициализации Adjust.
Прямые HTTP impression/click URL кросс-промо работают отдельно и этим флагом не отключаются.
Внешние вызовы `Adjust.InitSdk` из кода игры или автоматически запускаемый vendor-компонент
обходят ядро SDK; для этой интеграции запуском Adjust должно управлять только ядро.
