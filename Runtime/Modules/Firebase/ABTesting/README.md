# A/B-тесты через Firebase Remote Config

Вся логика находится в модуле Firebase. SDK выбирает зарегистрированную фичу по строковому
параметру Remote Config. Эксперимент, аудитория, доли групп и целевые метрики создаются в
Firebase Console; SDK не создаёт эксперимент на сервере и не распределяет пользователей случайно.

## Настройка

1. В **SDK Settings → Firebase** включите Firebase, **Enable Remote Config** и сохраните настройки.
   Для экспериментов Firebase A/B Testing также включите **Enable Analytics**.
2. Зарегистрируйте ID теста, явную контрольную группу и обработчики всех поддерживаемых групп.
3. В Firebase Console создайте строковый параметр Remote Config с тем же ID. Например:
   `shop_layout`, значение по умолчанию `control`.
4. Создайте эксперимент Remote Config в Firebase A/B Testing: выберите приложение,
   аудиторию, доли пользователей, варианты `control` / `variant_b` и целевую метрику.
   Значения должны точно совпадать с именами групп в коде, включая регистр.
5. Проверьте варианты на тестовых устройствах перед запуском эксперимента.

Официальная инструкция: https://firebase.google.com/docs/ab-testing/abtest-config

## Пример для игры

Вызывайте после создания SDK, обычно из `Start`. Фасад доступен и в сборках без Firebase.

```csharp
using AMZNGoDSDK.Runtime;
using UnityEngine;

public sealed class ShopExperiment : MonoBehaviour
{
    private const string TestId = "shop_layout";

    private void Start()
    {
        var sdk = AmznGoDSDKCore.Instance;
        if (sdk == null || !sdk.IsFirebaseEnabled)
        {
            ApplyControl();
            return;
        }

        sdk.RegisterABTest(TestId, "control");
        sdk.RegisterABTestFeature(TestId, "control", ApplyControl);
        sdk.RegisterABTestFeature(TestId, "variant_b", ApplyVariantB);
        sdk.RunABTest(TestId);
    }

    private void ApplyControl() { /* обычный магазин */ }
    private void ApplyVariantB() { /* новый магазин */ }

    private void OnDestroy()
    {
        // Освобождаем ссылки на этот объект и отменяем ещё не выполненный Run.
        // Для тестов на всю сессию владелец должен жить вместе с SDK.
        AmznGoDSDKCore.Instance?.RemoveABTest(TestId);
    }
}
```

`RegisterABTestFeature` заменяет ранее зарегистрированный обработчик той же группы.
Порядок регистрации вариантов не меняет контрольную группу. ID теста и группы должны быть
непустыми строками длиной до 100 символов (лимит параметров события SDK).

Через сам `FirebaseModule` доступны `RegisterTest`, `RegisterFeature`, `Run`,
`TryGetTestGroup`, `UnregisterFeature`, `RemoveTest`, `ClearAll`.
`RegisterFeature` принимает как `Action`, так и `AMZNGoDSDK.Runtime.ABTesting.ITestableFeature`.
Прямое использование этих типов оборачивайте в `#if AMZN_FIREBASE_ENABLED`.

## Выбор группы и ожидание

- До `RunABTest` обязательно зарегистрировать тест и обработчик контрольной группы.
- Вызовы `RunABTest` до завершения загрузки объединяются в один отложенный запуск на тест.
- После загрузки используется активированное удалённое значение, при сетевой ошибке —
  ранее активированное значение Firebase, если оно доступно.
- Отсутствующее, пустое или неизвестное значение приводит к контрольной группе.
- При выключенном Remote Config либо недоступных зависимостях Firebase используется контрольная группа.
- Контрольные значения хранятся в реестре SDK, а не через `SetDefaultsAsync`:
  регистрация после загрузки работает без повторного запроса и без гонки обновления defaults.
- Активированные удалённые значения фиксируются после начальной загрузки на время жизни модуля.
  В этой версии нет обновления групп посреди игровой сессии и нет принудительного повторного fetch.
- Повторный `RunABTest` после готовности повторно вызывает фичу, например для нового экрана.
  Обработчик должен корректно переносить такие вызовы. Рекурсивный запуск того же теста подавляется.
- Исключение внутри обработчика логируется; другие тесты продолжают работать.
  Событие участия для неуспешного запуска не отправляется.
- `RemoveABTest` удаляет обработчики, выбранную группу, отложенный запуск и отметку события.
  Повторная регистрация после удаления считается новым участием.
- При полном отключении Firebase фасад A/B-тестов ничего не выполняет; игра применяет базовый вариант сама,
  как показано в примере.

`IsFirebaseReady` сообщает о готовности Analytics/Crashlytics и **не ждёт Remote Config**.
`IsFirebaseRemoteConfigReady` означает завершение разрешения групп, включая переход к defaults при ошибке.
Он не доказывает успешное соединение с сервером. У модуля есть отдельное свойство
`LastRemoteConfigFetchSucceeded`, событие `OnInitialized` и событие `OnRemoteConfigReady`.
События не переигрываются для поздних подписчиков: сначала проверяйте соответствующее свойство.
Все вызовы API выполняйте в главном потоке Unity.

Если модуль Internet Connection блокирует общий запуск SDK до появления сети, инициализация
Firebase и отложенные A/B-вызовы также ждут этого запуска. Описанный офлайн-fallback относится
к уже запущенной инициализации Firebase; общий порядок запуска SDK здесь не меняется.

По умолчанию Remote Config выключен, чтобы обновление SDK не добавляло запросы в существующие игры.
После включения: таймаут fetch — **10 секунд**, минимальный интервал — **43 200 секунд (12 часов)**.
Настройки доступны в окне SDK. Для тестового устройства временно уменьшите интервал;
для релиза верните рабочее значение. Неуспешные запросы могут быть ограничены самим Firebase.
Нулевые/отсутствующие значения таймингов старого JSON заменяются указанными defaults.

## Аналитика участия

После успешного выполнения фичи отправляется `ab_test_exposure` с параметрами:

| Параметр | Пример |
| --- | --- |
| `test_id` | `shop_layout` |
| `group_name` | `variant_b` |

Событие передаётся в включённый и готовый Firebase Analytics и, если доступен,
в включённый и инициализированный AppMetricaModule. Ошибка одного получателя не мешает другому.
Повторное применение той же группы не создаёт повторное событие; `RemoveABTest` / `ClearABTests`
сбрасывают эту отметку. Это уведомление о применении фичи, а не очередь гарантированной доставки:
для отключённой/недоступной аналитики событие не сохраняется на будущее.

Для анализа параметров в GA4 настройте соответствующие custom dimensions.
Бизнес-метрики эксперимента (покупка, завершение уровня и т. п.) отправляются игрой отдельно.

## Проверка на устройстве

- Новый запуск: удалённые `control` и `variant_b` вызывают соответствующие обработчики.
- Без сети: ранее активированная группа сохраняется; без кэша выбирается `control`.
- Удалённая группа новой версии, неизвестная старому клиенту: выполняется `control`.
- Регистрация после загрузки и до загрузки даёт одинаковый выбор.
- Несколько ранних `RunABTest`: один запуск после готовности; удалённый до готовности тест не запускается.
- Повторное применение фичи не удваивает событие участия; ошибка обработчика не создаёт exposure.
- Analytics/Crashlytics работают во время ожидания Remote Config.
- Firebase / Remote Config / AppMetrica выключены по отдельности: сборка и локальные сценарии сохраняют описанное поведение.
