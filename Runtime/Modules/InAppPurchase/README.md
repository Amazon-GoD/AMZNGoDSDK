# In-App Purchase Module

Amazon Appstore IAP (Fire OS): подписки, расходуемые и разовые покупки.

**Модель (ТЗ «исправление IAP», ред. 3):** источник истины о правах — чек Amazon, а не
локальные даты. SDK **ничего не начисляет** — он сообщает состояние и события, начисляет игра.

## Контракт для игры — прочитать перед интеграцией

### 1. Готовность: два флага, не один

| Флаг | Значение |
|---|---|
| `IsIAPInitialized` | Сервис поднят: можно вызывать `BuyProduct`. Состоянию прав верить **рано**. |
| `IsIAPRestored` | Была успешная полная сверка с Amazon в этой сессии: состоянию можно верить. |

Не показывайте «подписки нет» до `IsIAPRestored` — до сверки состояние равно последнему
сохранённому значению прошлой сессии.

### 2. Состояние прав — трёхзначное

`GetIAPEntitlementState(sku)` → `Unknown` / `Entitled` / `NotEntitled`.

`Unknown` — «не проверяли», и это НЕ «прав нет»: любой сбой (сеть, ошибка Amazon, обрыв
пагинации) оставляет Unknown. `NotEntitled` ставится **только** по успешной полной сверке.

Legacy-методы `IsSubscribed(sku)` и `HasReceipt(sku)` отвечают **одинаково** (раньше врали в
разные стороны) и пока состояние Unknown отдают последнее сохранённое значение, а не false.
Грейс: доступ снимается, если сверка не удавалась дольше **7 суток + `Term (days)` подписки**
(для разовых покупок — просто 7 суток): игрок, ушедший в офлайн на один оплаченный период
недельной подписки, доступ не теряет.

**Свежая покупка защищена от гонки со сверкой**: история чеков у Amazon доезжает с
непредсказуемой задержкой, и сверка, запущенная сразу после покупки, может ещё не видеть
свежий чек. Право, выданное живой покупкой, не отзывается по «нет чека в снапшоте» в течение
10-минутного защитного окна (строго по SKU; отметка персистится и переживает перезапуск).
Отметка снимается, как только чек впервые появился в снапшоте, — дальше SKU живёт по общим
правилам, включая честный отзыв по рефанду.

`HasReceipt` покрывает только долгоживущие права (подписка, разовая покупка). Для «покупал ли
когда-либо» (включая расходуемые) — `HasEverPurchasedIAP(sku)`.

### 3. События — на что подписаться

```csharp
var sdk = AmznGoDSDKCore.Instance;

// Права выданы. ВНИМАНИЕ: это сигнал состояния «игрок этим владеет», он приходит при
// КАЖДОМ запуске (история чеков приезжает целиком каждый раз) и доигрывается поздним
// подписчикам. Обработчик ОБЯЗАН быть идемпотентным и НЕ должен начислять валюту.
sdk.AddIAPEntitlementGrantedListener(e => EnablePremium(e.ProductId));

// Права сняты: истечение подписки (по сверке), возврат денег, отмена.
// Уже начисленное НЕ отбираем — снимается только доступ.
sdk.AddIAPEntitlementRevokedListener(e => DisablePremium(e.ProductId));

// Начался новый оплаченный период подписки — ЗДЕСЬ начисляйте награду за период.
// Приходит ровно один раз на период (журнал в SDK), включая догон после офлайна.
sdk.AddIAPPeriodStartedListener(p => GrantWeeklyReward(p.ProductId, p.PeriodIndex));

// Покупка завершена. Для расходуемых приходит ровно один раз на чек (в т.ч. при
// восстановлении после переустановки) — здесь начисляйте товар.
sdk.SetIAPPurchaseCompleteCallback(productId => GrantConsumable(productId));
sdk.SetIAPPurchaseFailedCallback(productId => ShowPurchaseFailed(productId));
```

### 4. Что SDK больше НЕ делает

- **Не начисляет монеты и предметы.** `SetIAPConsumableRewardSetter`, типы наград и поля
  наград в настройках удалены. Старый код начислял ноль монет в жёстко зашитый ключ
  `TotalCoins` — фактической потери нет, но игра ОБЯЗАНА подписаться на события и начислять
  сама, иначе подписка перестанет давать что-либо осознанно, а не по ошибке.
- **Не продлевает подписку локальной датой.** `DurationDays` больше не управляет доступом.

### 5. Периоды подписки и доверенное время

Продления у Amazon не наблюдаются (при продлении не меняется ни одно поле чека), поэтому
периоды вычисляются: якорь — `PurchaseDate` чека, длина — `Term (days)` из настроек,
«сейчас» — доверенное время из заголовка `Date` HTTP-ответов бэкенда (часы устройства игрок
может перевести — защита храповиком). Без сети периоды не начисляются и ждут первого
онлайна — тогда выдаются все накопленные разом: живая покупка сразу ставит якорь в журнале
периодов, поэтому купленная при недоступном бэкенде подписка ничего не теряет, даже если
время появится спустя несколько периодов. После переустановки прошлые периоды не
выдаются повторно, текущий — выдаётся (якорь при восстановлении сознательно не ставится —
иначе переустановка выдавала бы всю историю). Смена тарифа обрабатывается защитно: `deferredDate`
чека — потолок периодов старого SKU, новый SKU считается со своего чека (по данным портфеля
ни одна подписка тариф не меняла — это страховка, не рабочий сценарий).

`Term (days)` обязателен для каждой включённой подписки: без него не сохранятся настройки и
не соберётся билд. Укажите реальный период из консоли Amazon (7 для недельной).

**Смена `Term (days)` у живой подписки ретроактивна**: журнал хранит номер периода, а не
дату, поэтому исправление 30 → 7 разом доначислит «пропущенные» периоды, а 7 → 30 заморозит
события до догона. Ставьте срок правильно с первого раза; исправление мисконфига — осознанная
операция с этим эффектом.

### 6. Аналитика (AppMetrica)

- Воронка: `iap_purchase_started` → `iap_purchase_success` (`new` / `already_owned`) /
  `iap_purchase_failed` (`{"sku":{"reason":{"online|offline":""}}}`). Отдельные reason'ы:
  `pending` — ожидание одобрения родителем (Amazon Kids, не отказ);
  `receipt_not_processed` — стор ответил SUCCESSFUL, но чек не удалось обработать
  (SKU не настроен / тип разошёлся) — игра получает failed, чек догонит сверка после
  исправления настроек.
- `already_owned` включает и повторное нажатие «купить», на которое Amazon ответил
  `ALREADY_PURCHASED` без чека: в воронке это не отказ, но игра получает failed-колбэк —
  ничего нового не выдано, право подтвердит сверка.
- **`store_failed` — это в основном «игрок передумал»**: Amazon IAP v2 не отдаёт отдельного
  статуса отмены, закрытие окна покупки приходит как FAILED. Не читайте график как поломку.
- `iap_purchase_restored` — восстановленные расходуемые (вне воронки, у них нет started).
- `iap_catalog_failed` — отказы каталога (`catalog_request_failed` / `catalog_response_failed`
  / `sku_unavailable` / `init_error`), дедуп в пределах сессии.
- `iap_entitlement_revoked` — снятие права сверкой: по нему виден массовый отзыв.

### 7. Известные ограничения

- **Push об истечении подписки недоступен**: легаси-мост регистрирует пять событий,
  subscription-expired среди них нет. Истечение обнаруживается сверкой (старт + возврат из
  фона при устаревании > 5 минут).
- **Баланс расходуемых после переустановки не восстанавливается**: Amazon не возвращает
  выданные расходуемые товары, а купленные монеты живут в PlayerPrefs. Свойство архитектуры,
  лечится только сервером. Подписки и разовые покупки восстанавливаются полностью.
- Повторное нажатие «купить» до ответа отклоняется с reason `purchase_in_progress`
  (окно 90 секунд — брошенный диалог покупки не блокирует магазин навсегда).
- **Гонка атрибуции закрыта по RequestId**: ответы покупки и сверки матчатся с запросом по
  RequestId моста. Поздний ответ брошенной покупки не закрывает текущую и не крадёт её
  атрибуцию (чек из него всё равно обрабатывается — деньги могли списаться); поздняя
  страница мёртвого прогона сверки отбрасывается и не может примениться как неполный
  снапшот прав. Когда RequestId сравнить не с чем (editor-стаб, симулятор), матчинг мягкий —
  ответ считается своим.
- **Терминал чужого ответа** уходит в воронку по SKU из чека (его started уже отправлен,
  иначе started ≈ success + failed ломается на мультитапах); текущая покупка при этом не
  трогается. Остаточное ограничение: чужой ответ БЕЗ чека (типичный FAILED брошенного
  диалога) закрыть нечем — SKU неизвестен, его started остаётся незакрытым.
- **PENDING (Amazon Kids)**: покупка, ждущая одобрения родителя, приходит игре как failed с
  reason `pending`; после одобрения чек приедет в истории и выдастся сверкой. Как именно
  легаси-мост передаёт статус PENDING (строкой или как FAILED) — проверить App Tester'ом.
- **Term SKU подписки**: если чек приходит с term SKU вместо родительского (квирк Amazon,
  раздел H ТЗ), матчинг фолбэком приводит его к настроенному SKU: точный `TermSku`, затем
  единственный настроенный префикс среди подписок. Неоднозначный префикс не угадывается —
  чек лежит необработанным до исправления настроек.
- Если покупка упала исключением при вызове (в воронке `failed`), а нативка позже всё же
  прислала SUCCESSFUL — товар выдаётся; success не шлётся, пока не начата следующая покупка
  (терминал воронки один на started). Если же к моменту позднего ответа уже идёт другая
  покупка, ответ считается чужим и success уйдёт по SKU из чека — такая покупка получит в
  воронке и failed, и success (редкий двойной терминал, осознанный трейдофф в пользу
  закрытия started у мультитапов).
- PlayerPrefs-ключи старой схемы для SKU, удалённых из настроек ДО обновления SDK, миграция
  вычистить не может (PlayerPrefs не перечисляется) — безвредный мусор.

## Настройка в Editor

1. `AMZN GoD → SDK Settings`, включите **In-App Purchase**.
2. Продукты (Product ID = SKU из Amazon Developer Console; тип в настройках должен совпадать
   с типом в консоли — при расхождении чек не обрабатывается, в логе ошибка):
   - **Subscription Products** — подписки (+ обязательный `Term (days)`);
   - **Consumable Products** — расходуемые;
   - **Non-Consumable Products** — разовые покупки (убрать рекламу, анлок): право выдаётся
     один раз и не теряется, кроме возврата денег.
3. `Enabled` продукта управляет только тем, что можно **купить**: уже оплаченное работает
   независимо от него.

## Хранилище (PlayerPrefs, схема v1)

`AMZN_IapSchemaVersion`, `AMZN_GrantedReceipts` (идемпотентность выдачи),
`AMZN_PendingFulfillment` (выдано, Amazon не подтвердил — повтор на старте без повторной
выдачи), `AMZN_Entitlements` + `AMZN_EntitlementReconciledAt` (снимок прав последней успешной
сверки), `AMZN_PeriodJournal` (выданные периоды по ReceiptId), `AMZN_EverPurchasedSkus`,
`AMZN_LiveGrantProtection` (отметки защитного окна живых покупок), `AMZN_TrustedTimeUtc`
(храповик времени). Миграция со старой схемы (`AMZN_FulfilledReceipts`,
`SubscriptionExpires_*`) выполняется автоматически один раз, старый журнал засевает новый —
без повторных начислений у существующих игроков.

Журнал выдач ограничен 2000 записями: при переполнении отбрасываются самые старые
подтверждённые записи (не pending и не подписочные) — такие чеки Amazon в истории уже не
возвращает, повторная выдача по ним невозможна.

## Нативные зависимости (Plugins/Android)

| Файл | Что это |
|---|---|
| `amazon-appstore-sdk-3.0.9.jar` | Amazon Appstore SDK — IAP + DRM + Simple Sign-in |
| `AmazonIapV2Client.jar`, `AmazonIapV2JavaService-1.0.jar`, `AmazonCptPluginsUtils-1.0.jar`, `gson-2.2.4.jar`, `libs/*/libAmazonIapV2Bridge.so` | легаси Unity-плагин Amazon IAP V2 (JNI-мост, через который ходит C#) |
| `AmazonIapV2Compat.jar` | шим: возвращает удалённый в 3.0.9 класс `com.amazon.android.CrossPlatformPluginUtils`, без него легаси-плагин падает с `NoClassDefFoundError` при инициализации. Исходник и обоснование — в `AmazonIapV2Compat~/` |

Манифест: `com.amazon.device.iap.ResponseReceiver` (и DRM-аналог) обязаны быть объявлены в
манифесте — без них Appstore не доставляет ответы `PurchasingListener`. Туда же нужен
`AmznGoDIapBootstrapProvider` — поднимает Appstore SDK до первой активити, иначе окно покупки
не показывается («No UI visible») — и `<queries>` на пакеты Appstore/App Tester (package
visibility с targetSdk 30+). Вручную ничего прописывать не нужно: при включённом модуле все
недостающие записи дописывает в манифест Gradle-проекта `IapManifestInjector`
(`Editor/SdkModulesSettings/IapManifestInjector.cs`) на этапе сборки; уже объявленные записи
(например, в `Assets/Plugins/Android/AndroidManifest.xml` этого проекта) он не дублирует.
С выключенным модулем записи вырезает `DisabledModuleManifestCleaner`.

**Ограничение:** `libAmazonIapV2Bridge.so` собран только под 32-бит (`armeabi-v7a`, `armeabi`, `x86`) —
arm64-сборка с этим плагином работать не будет. Проект сейчас собирается под ARMv7
(`AndroidTargetArchitectures: 1`). Для перехода на arm64 легаси-плагин надо заменить прямыми
вызовами `com.amazon.device.iap.PurchasingService` через `AndroidJavaClass`/`AndroidJavaProxy`.

## Устройство модуля

`InAppPurchaseModule` — оркестрация и публичный API. Механика в `Core/`:

| Файл | Роль |
|---|---|
| `IapServiceGateway` | шов к плагину Amazon: каждый бросок → false + причина; подменяем в тестах |
| `IapProductCatalog` | продукты из настроек: известные SKU ≠ SKU к запросу каталога; `Enabled` читается только в `CanBuy` |
| `IapReceiptJournal` | журналы чеков: выдано / не подтверждено Amazon / выданные периоды; миграция v1 |
| `IapEntitlementStore` | трёхзначное состояние, грейс, «bool никогда не врёт false из-за незнания» |
| `IapReconcileSession` | накопитель полного ответа GetPurchaseUpdates → неизменяемый снапшот |
| `IapSubscriptionPeriods` | чистый калькулятор периодов (см. таблицу тестов в истории задачи) |
| `IapRetryScheduler` | бэкофф 2/8/30 с, single-flight, повтор на форграунде |
| `IapAnalytics` | все события; ни один репорт не может уронить покупку |

## Тестирование

- **Amazon App Tester** на устройстве Fire OS — единственная полноценная проверка.
- В редакторе: `Testing/IAPTestPanel` + `SimulatedAmazonStore` подают ответы стора через ту
  же точку входа, что и JNI-мост, — исполняется настоящий код модуля. Build Target — Android.
- Панель играет роль игры: начисляет демо-монеты по событиям SDK.
- Кнопки панели: `BUY SUBSCRIPTION` / `BUY CONSUMABLE` / `BUY NON-CONSUMABLE` — покупка
  (повторная покупка долгоживущего права отвечает `ALREADY_PURCHASED`); `WIPE SDK STATE` — полный
  сброс к чистой установке (журналы, права, чеки симулятора, демо-монеты) — **действует
  после перезапуска** Play Mode/приложения. Восстановление тестируется переустановкой игры
  (на устройстве история чеков живёт у Amazon и приезжает авто-сверкой при старте).
  Панель **создаётся автоматически** при включённом модуле IAP (руками добавлять в сцену
  не нужно; добавленная вручную имеет приоритет) и собирается в любой билд с включённым
  IAP, включая релизный — QA тестирует на релизных билдах, потому что Development Build
  падает на Vulkan-баге эмулятора BlueStacks (`vkSetDebugUtilsObjectNameEXT`,
  дебаг-маркеры Unity в dev-билдах).
