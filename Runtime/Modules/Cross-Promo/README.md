# Cross-promo: мастер JSON

В `AMZN GoD → SDK Settings → Cross Promo → Config URL` можно указать один URL
мастер-файла для всех игр. При запуске SDK скачивает мастер, находит запись с
`PackageName`, совпадающим с `Application.identifier` текущей игры, и загружает
JSON с креативами по её `ConfigUrl`.

## Формат мастер-файла

```json
{
  "Packages": [
    {
      "PackageName": "com.example.gameone",
      "ConfigUrl": "https://cdn.example.com/cross-promo/gameone.json"
    },
    {
      "PackageName": "com.example.gametwo",
      "ConfigUrl": "https://cdn.example.com/cross-promo/gametwo.json"
    }
  ]
}
```

Готовый шаблон: [master.example.json](master.example.json). Замените примерные
package name и URL своими значениями перед размещением файла.

- Имена полей чувствительны к регистру: `Packages`, `PackageName`, `ConfigUrl`.
- `PackageName` — идентификатор самой игры, загружающей рекламу, из Player Settings.
  Это не `AppPackageName` рекламируемого приложения в JSON креативов.
- Для каждой игры должна быть ровно одна запись с точным совпадением package name.
  Несколько игр могут ссылаться на один JSON с креативами.
- `ConfigUrl` записи — полный URL по HTTP или HTTPS. Рекомендуется HTTPS.
- Поддерживается один уровень: мастер → JSON с креативами. Ссылки на другой
  мастер не поддерживаются.
- Мастер содержит `Packages`; конечный JSON — прежние `Weight` и `Videos`.
  Не объединяйте `Packages` и `Videos` в одном документе.

Формат креативов, веса и фильтры установленных приложений не изменены.
Прямой URL прежнего JSON с `Videos` также продолжает работать в том же
поле `Config URL`.

## Лимиты показов и AppLovin

Лимиты кросс-промо (`cap`, либо `MaxShowCount` в старых конфигах) применяются
только при включённом модуле AppLovin. Если модуль выключен в SDK Settings или
исключён из сборки, даже достигшие лимита креативы остаются доступны для показа
и предзагрузки. При включённом модуле лимиты действуют независимо от готовности
рекламы MAX.

Счётчики показов сохраняются и продолжают накапливаться. После повторного
включения AppLovin и перезапуска SDK лимиты снова учитывают накопленные показы.
Кулдауны и фильтры установленных приложений и собственной игры работают как прежде.

## Как переключить JSON без пересборки

1. Один раз обновите SDK в игре до версии с поддержкой мастера, задайте URL
   размещённого мастер-файла в `Config URL` и выпустите обновлённую сборку.
2. Разместите новый JSON с креативами по доступному URL.
3. Измените `ConfigUrl` нужной игры в мастер-файле, оставив URL самого мастера
   прежним. Опубликуйте обновлённый мастер.
4. При следующем запуске игры SDK прочитает мастер заново и загрузит новый JSON.
   Последующие переключения выполняются только на сервере.

Успешно загруженный конфиг действует до конца текущей сессии: периодического
опроса и переключения во время показа рекламы нет. Если начальная загрузка не
дала доступных креативов, сохраняются существующие фоновые повторные попытки SDK.

Настройте кеширование хостинга/CDN так, чтобы изменённый мастер был доступен на
следующем запуске: например, `Cache-Control: no-cache` с проверкой актуальности
или инвалидация кеша при публикации. Настройки CDN могут требовать отдельной
инвалидации. Конечный JSON тоже должен быть актуальным; при длительном TTL удобно
публиковать его по новому URL и менять ссылку в мастере.

## Ошибки и диагностика

Если package name отсутствует или повторяется, URL неверен, JSON повреждён либо
конечный файл тоже является мастером, SDK сообщает причину в логах
`[CrossPromoConfig]`. Чужая запись вместо нужной игры не выбирается. При неудачной
загрузке возвращается пустой конфиг и действует существующий путь `no_fill` /
медиации и повторных попыток.

Меню `AMZN GoD → Debug → Cross-Promo Caps` также читает мастер по package name
текущего проекта и работает с конечным JSON с креативами.
